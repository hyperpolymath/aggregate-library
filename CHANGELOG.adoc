==== Changed

* Extracted into a standalone top-level repository
(`+hyperpolymath/aggregate-library+`), split out of the
`+developer-ecosystem+` monorepo with full history preserved.
* Deduplicated documentation: removed duplicate `+.adoc+`/`+.md+` pairs,
keeping the richer copy in each case (`+CONTRIBUTING.adoc+`;
`+CHANGELOG.md+`, `+CODE_OF_CONDUCT.md+`, `+MAINTAINERS.md+`).
* `+string/substring+`: the spec now states zero-based indices, `+start+`
inclusive and `+end+` exclusive, that the third argument is an index and
not a length, the conformance domain `+0 ≤ start ≤ end ≤ length(s)+`, and
what a conformer may do outside it. Two boundary vectors added.
* The AffineScript conformer's `+substring+` takes `+(s, start, end)+`, as
the spec does, instead of `+(s, start, len)+`.
* `+string/length+` and `+string/substring+`: the character unit is now
defined as the Unicode scalar value (it was implementation-defined), so a
substring index can never split a UTF-8 or UTF-16 encoding. Non-ASCII
vectors added: `+length("é") = 1+`, `+substring("éa", 0, 1) = "é"+`,
`+substring("éa", 1, 2) = "a"+`.

==== Added

* `+vectors/<category>.json+`: the spec test vectors exported as I-JSON in
JCS form, with `+vectors/GRAMMAR.adoc+` (JSON layout and an EBNF grammar
for lambda and condition strings), `+scripts/export-vectors.sh+`, and the
`+just vectors+` / `+just vectors-check+` recipes. `+just validate+` now
fails if the exported vectors drift from the specs, if a vector's arity
does not match its signature, or if a lambda or condition is malformed.
The exporter also rejects a signature whose name differs from its file
name, a lambda parameter list that does not alternate identifier and comma,
a Boolean argument that is neither a Boolean nor a condition string, and any
number or string jq cannot write in JCS form (exponent-form numbers,
integers beyond 2^53 - 1, NaN, U+007F); `+ijson-jcs check+` runs on the
output when that CLI is on `+PATH+`. `+test/vectors-guards.sh+`
(`+just vectors-test+`, part of `+just validate+`) covers each rejection
with a positive control. `+just deps+` and `+just setup+` require jq 1.7 or
later and a supported yq.

==== Fixed

* `+logical/not+` vector 3 expected `+not(true)+` to be `+true+`. It now
passes the condition `+"not(true)"+`, so it tests double negation as its
description says.
* Justfile: the spec recipes globbed `+specs/*/*.md+`, but the specs are
`+.adoc+`, so `+just validate+` and `+just test+` always failed. The
per-category recipes now list all 29 specs and fail on a missing or extra
file; `+validate-specs+` checks AsciiDoc headings and stops at the first
bad spec instead of only reporting the last one.
* Operation counts (29 / 22 / 20) reconciled; see the README section "The
operations".

==== Design Decisions

* *Minimal Scope*: Common Library contains only operations that exist
across ALL seven target languages (WokeLang, Duet/Ensemble, Eclexia,
Oblíbený, RT-Lang, Phronesis, Julia the Viper)
* *Specification-Only*: This repository contains specifications, not
implementations
* *Language-Agnostic*: All specifications avoid language-specific
assumptions
* *Testable*: Every operation includes concrete, executable test cases
in YAML format
* *Offline-First*: All operations are air-gap compatible, no network
operations
* *Type-Minimal*: Uses only basic type categories (Number, String,
Boolean, Collection, Function)

==== Philosophy

This release establishes the foundation for cross-paradigm,
cross-language software development by: - Reducing programming language
territoriality - Providing a shared vocabulary across radically
different paradigms - Enabling polyglot development with consistent
primitives - Preserving language-specific features in Standard Libraries

=== Version History

==== Version Numbering

We follow Semantic Versioning (semver): - *Major* (x.0.0): Breaking
changes to specifications - *Minor* (0.x.0): New operations or
significant additions - *Patch* (0.0.x): Clarifications, fixes,
documentation improvements

==== Breaking Changes Policy

Breaking changes will be: - Clearly marked in CHANGELOG - Announced with
sufficient notice (minimum 6 months for 1.0+) - Discussed with community
before implementation - Minimized wherever possible

==== Deprecation Process

When operations or specifications need to be deprecated: 1.
*Announcement*: Marked as deprecated in documentation 2. *Grace Period*:
Minimum 2 releases or 12 months (whichever is longer) 3. *Migration
Guide*: Provide clear migration path 4. *Removal*: Remove in major
version update only

=== Release Process

==== Release Criteria

Releases happen when: - Significant new specifications added (minor
version) - Important clarifications or fixes accumulated (patch version)
- Major redesign or breaking changes (major version) - Time-based: At
least every 6 months if changes exist

==== Release Checklist

Before each release: - [ ] All tests pass - [ ] Documentation updated -
[ ] CHANGELOG.md updated - [ ] README.md updated with version number - [
] Git tag created - [ ] GitHub release created with notes - [ ]
Community announcement posted
